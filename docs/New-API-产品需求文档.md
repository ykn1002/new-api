## 1. 产品背景与目标

### 1.1 背景

随着 AI 大模型应用普及，开发者和企业需要同时接入多家服务商（OpenAI、Claude、Gemini 等），却面临接口格式不统一、密钥难以分发管控、价格体系混乱、多团队用量难以隔离结算等问题。New API 通过一个统一的、兼容 OpenAI 的中转层解决这些问题。

### 1.2 产品目标

| 目标 | 描述 |
| --- | --- |
| 统一接入 | 用户替换 `base_url` 即可调用多家服务商，无需改造客户端 |
| 凭证可控 | 通过令牌实现配额、模型、IP、分组维度的精细化管控 |
| 计费灵活 | 三层倍率体系支持多模型、多用户组的差异化定价 |
| 多租户隔离 | 分组机制隔离不同用户的渠道权限与计费标准 |
| 商业化闭环 | 内置充值、订阅、兑换码、邀请返利，支撑 API 转售运营 |

### 1.3 价值主张

- 对开发者：一个入口、一个令牌，调用所有模型，用量花费一目了然。
- 对管理员：渠道负载与容灾、用户与配额管理、全平台用量分析。
- 对运营方：完整的计费与变现能力，可对外开展 API 转售业务。

### 1.4 范围

- 包含：账号体系、令牌、API 网关、计费、充值/订阅、渠道/用户/模型管理、系统配置、异步任务、监控。
- 不包含：上游模型自身的推理实现；ChatGPT Next Web 部署（已暂停）。

> 说明：本 PRD 已对照后端源码补全。相较初版，本版新增以下已落地能力：每日签到奖励、敏感词内容过滤、表达式动态/阶梯计费、视频/音乐异步生成、渠道亲和（粘性路由）、WeChat/Telegram 登录、订阅配额周期重置、SSRF 防护与性能监控等（详见对应章节）。

## 2. 用户画像与核心场景

### 2.1 用户画像

**画像一：独立开发者 小李**
- 背景：个人开发 AI 应用，需要调用多种模型做对比测试。
- 诉求：快速拿到可用 API、清楚每次调用花多少钱、能限制单个令牌的额度防止超支。
- 痛点：直接用多家官方 API 要管理多套密钥和账单。

**画像二：团队管理员 王工**
- 背景：负责公司内部 AI 平台运维，给多个业务团队分配资源。
- 诉求：统一管理上游渠道、给不同团队分配配额和分组、监控全平台用量、保障高可用。
- 痛点：上游某个 Key 失效会影响全员；难以按团队分摊成本。

**画像三：平台运营方 Root 张总**
- 背景：以 API 转售为业务，对外提供付费 AI 接口服务。
- 诉求：灵活定价、接入支付收款、配置安全与注册策略、监控系统健康。
- 痛点：缺乏一套能直接变现的计费与运营体系。

### 2.2 核心场景

1. 快速接入调用：开发者注册 → 创建令牌 → 复制 API 地址 → 在代码或操练场中调用。
2. 成本管控：用户为不同项目创建独立令牌并设置配额上限，超额自动失效。
3. 充值续费：用户通过在线支付或兑换码充值，或购买周期性订阅套餐。
4. 渠道运维：管理员配置多渠道、多 Key，做负载均衡与失败自动切换。
5. 用量结算：管理员按用户/模型/渠道维度查看全平台消耗，做成本分摊。
6. 平台运营：Root 配置计费倍率、支付渠道、注册与安全策略，对外开展业务。

## 4. 核心业务概念

- 配额（Quota）：平台内部统一计费单位，用户余额、消费均以配额计。
- 令牌（Token）：调用 API 的凭证，可独立设置配额上限、可用模型、IP 白名单、所属分组。
- 渠道（Channel）：对接某家上游服务商的配置单元，承载该服务商的一个或多个 API Key。
- 分组（Group）：隔离单位，决定用户/令牌能使用哪些渠道，以及享受何种计费倍率。
- 倍率（Ratio）：计费调节系数，分为模型倍率、补全倍率、分组倍率三层。
- 异步任务（Task）：Midjourney 绘图、Suno 音乐、视频生成等需要等待的生成任务。
- 表达式计费：以单条表达式承载某模型全部定价逻辑的动态/阶梯计费机制。
- 邀请与签到：邀请返利与每日签到，作为获客与活跃运营手段。

概念关系：用户持有多个令牌；用户和令牌都归属某个分组；渠道对特定分组开放；调用产生日志并扣减配额。

## 6. 用户端功能需求

> 每个模块包含：用户故事、功能说明、验收标准、异常与边界。

### 6.1 注册与登录

**用户故事**：作为访客，我希望用账号密码或第三方账号快速注册登录；忘记密码时能自助找回。

**功能说明**
- 账号密码注册：填写用户名、密码、邮箱，并通过邮箱验证码校验；注册成功发放新用户初始配额并自动登录。
- 账号密码登录：入口为首页「登录」或 `/login`；若开启 2FA，密码后需补充动态码。
- 第三方 OAuth/社交登录：支持 GitHub、Discord、LinuxDO、自定义 OIDC、WeChat（微信扫码）、Telegram（Bot 登录）等，授权后自动登录；同一账号可绑定多个第三方身份用于免密登录。
- 自定义 OAuth 提供商：管理员可在后台注册任意符合 OpenID Connect Discovery 的提供商，无需改代码即可扩展登录方式。
- 忘记密码：输入注册邮箱接收重置链接，重置后原密码失效。

> 登录方式全集（源码核对）：账号密码、邮箱验证码、2FA/TOTP（含一次性备用码）、Passkey/WebAuthn、GitHub、Discord、LinuxDO、OIDC、WeChat、Telegram、自定义 OAuth。

**验收标准**
- 验证码错误或过期时拒绝注册并提示。
- 用户名重复时注册失败。
- 「开放注册」关闭时，普通注册入口不可用。
- OAuth 授权取消/失败时返回登录页并提示，不创建账号。
- 重置链接有时效且单次有效。

**异常与边界**
- 邮件服务未配置时无法发送验证码，需给出可读错误。
- 邮箱白名单开启时，非白名单域名注册被拒绝。

### 6.2 个人设置（`/console/personal`）

**用户故事**：作为用户，我希望管理账号信息、加固安全、配置通知与计费偏好。

**功能说明**
- 基本信息：修改用户名；绑定邮箱（验证码校验）；更改密码（校验当前密码 + 两次新密码一致）。
- 双因素认证 2FA：扫码绑定验证器 → 输入动态码确认开启 → 展示一次性备用码。
- Passkey：基于设备指纹/面容/硬件密钥的无密码登录。
- 第三方账号绑定：绑定后可免密登录。
- 重置 API 密钥：怀疑泄露时重置，旧密钥及所有现存令牌立即失效。
- 可用模型查看：展示可调用模型，支持搜索与点击复制。
- 通知设置：邮件通知（配额不足、令牌过期、系统公告）；Webhook 通知（填 URL、选事件、可测试，推送 JSON）。
- 价格策略：「拒绝未定价模型」（默认/推荐）或「允许未定价模型」。
- IP 记录：开启后日志展示调用来源 IP。

**验收标准**
- 当前密码错误时拒绝改密；两次新密码不一致时阻止提交。
- 2FA 动态码校验失败不开启；备用码仅展示一次，丢失需管理员重置。
- 重置 API 密钥前须二次确认，明确告知所有令牌将失效。
- Webhook「测试」应实际发起请求并反馈结果；非法 URL 阻止保存。
- 选择「允许未定价模型」时提示高额消耗风险。

### 6.3 令牌管理（`/console/token`）

**用户故事**：作为用户，我希望为不同用途创建独立令牌并设置额度与权限，隔离风险、控制成本。

**功能说明 — 创建令牌可配置项**

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| 名称 | 建议按用途命名 | 必填 |
| 过期时间 | 留空或 -1 永不过期 | -1 |
| 剩余配额 | 可消耗最大配额，超出失效 | — |
| 无限配额 | 不受令牌配额限制（仍受账户总配额约束） | 关 |
| 模型限制 | 限定可调用模型，空为不限 | 不限 |
| IP 白名单 | 限定来源 IP（支持 CIDR 网段），空为不限 | 不限 |
| 分组 | 指定渠道分组，可设 `auto` | 默认 |
| 跨组重试 | 仅 `auto` 分组生效：单组失败时跨分组容灾重试 | 关 |

- 令牌 Key 仅在创建时完整展示一次，需立即复制保存；列表中默认遮挡，重新查看完整 Key 需经「安全验证」并受关键操作限流保护。
- 单用户可创建令牌数量受系统配置 `max_user_tokens` 约束。
- 支持编辑（除 Key 外）、删除（立即失效不可恢复）。
- 列表展示名称、状态、已用配额、剩余配额、过期时间。

**验收标准**
- 令牌配额耗尽或到期后自动失效，调用被拒绝。
- 调用模型限制外的模型返回明确错误。
- 非 IP 白名单来源调用被拒绝。
- 无限配额令牌在账户总配额为 0 时仍不可用。

**令牌状态流转**：正常 →（配额耗尽 / 到期 / 被禁用）→ 失效；失效可重新启用；删除不可恢复。

### 6.4 API 调用能力

**用户故事**：作为开发者，我希望像调用 OpenAI 一样调用平台，无需改造现有代码。

**功能说明**
- 以平台地址为 `base_url`、令牌为 `api_key` 调用；首页提供 Base URL 一键复制。
- 操练场（`/console/playground`）：选模型 → 输入消息 → 查看回复，无需编码即可测试。
- 支持端点：聊天补全、文本补全、向量嵌入、图像生成/编辑、语音转文字（STT）、文字转语音（TTS）、语音翻译、重排序（Rerank）、内容审核（Moderations）、Responses API（含 compact 变体）、实时对话（WebSocket Realtime）、视频生成（异步）、模型列表。
- 原生格式兼容：Claude（`/v1/messages`）、Gemini（`/v1beta/...:generateContent`、原生 models 路径）。
- 多模态与高级能力：视觉/图文输入、函数调用（Tool Use）、Prompt 缓存、扩展思考/推理（thinking 模型）、Web 搜索（Claude 等）。系统按上游能力自动适配，并参与计费（见第 9 章）。

**验收标准**
- 合法令牌调用返回符合 OpenAI 规范的响应结构。
- `stream=true` 时返回流式分块。
- 令牌无效/过期/超配额返回标准错误。
- 模型列表接口仅返回该令牌/分组可用模型。

### 6.5 聊天应用集成

**用户故事**：作为用户，我希望把配置快速导入到常用 AI 聊天应用。

**功能说明**
- 一键导入：令牌页选目标应用 → 自动跳转并填充配置（支持 AI as Workspace、AMA 问天、OpenCat 等）。
- 手动配置：对不支持一键导入的应用（如 Lobe Chat），提供 API Base URL + API Key 填写指引。
- 配置变量：`{key}`→密钥，`{address}`→服务器地址（末尾不含 `/` 和 `/v1`）。

**约束**：ChatGPT Next Web 暂停部署；部分应用需先安装客户端。

### 6.6 定价查看（`/pricing`）
- 列出所有可用模型的输入/输出价格，支持按模型名搜索。
- 说明计费规则（每 1K Token 单价）并体现分组倍率差异。

### 6.7 使用记录与数据统计
- 日志（`/console/log`）：展示自身调用记录（时间、模型、Token、配额、状态），普通用户仅见自己的记录。
- 过滤：时间范围、模型、令牌名。
- 数据看板（`/console`）：折线/柱状图展示每日调用量与配额消耗趋势，悬停查看明细。
- 开启 IP 记录的用户，日志可见来源 IP。

### 6.8 配额与充值（`/console/topup`）

**用户故事**：作为用户，我希望多种方式充值，并通过邀请获得奖励。

**功能说明**
- 充值方式：兑换码、EPay（支付宝/微信）、Stripe、Creem、Waffo、Waffo Pancake。
- 在线支付：选金额 → 选渠道 → 跳转支付 → 回跳更新余额。
- 兑换码充值：输入兑换码 → 校验 → 成功增加配额并提示获得数量。
- 邀请返利：每账号有唯一邀请码；被邀请人注册成功后邀请人获一次性奖励配额；返利可转入主余额。

**验收标准**
- 兑换码无效/已用时明确报错，不重复入账。
- 支付回调须验签，防伪造入账。
- 金额低于该方式最低充值额时阻止发起并提示。
- 充值折扣生效时，实付与节省金额计算正确。

### 6.9 订阅计划（`/console/subscription`）
- 展示可购套餐（名称、副标题、价格、币种、有效期、含配额），支持时/日/周/月/年及自定义秒数周期。
- 购买后有效期内享受套餐配额/特权；顶部展示当前订阅状态。
- 套餐配额可按周期自动重置：不重置 / 每日 / 每周 / 每月 / 自定义周期；适配「按周期发放额度」型套餐。
- 购买套餐可触发用户分组升级（`upgrade_group`），享受对应分组的渠道权限与计费倍率。
- 支持单用户最大购买次数限制（0 为不限）。
- 支付方式：账户余额、EPay、Stripe、Creem、Waffo Pancake（套餐侧可分别绑定 `stripe_price_id` / `creem_product_id` / `waffo_pancake_product_id`）。
- 支持到期自动续费。
- 套餐下架不影响已购订阅。

### 6.9.1 每日签到（Check-in）
- 用户每日可签到一次，获得随机配额奖励（区间由系统配置的最小/最大值决定，默认 1000~10000 配额）。
- 同一自然日不可重复签到（数据库层面唯一约束保证）。
- 可由 Root 在运营设置中开关该功能并设定奖励区间。

### 6.10 任务管理（`/console/task`）
- 展示异步任务（ID、类型、状态、提交/完成时间）。
- 任务类型覆盖：Midjourney 绘图、Suno 音乐、视频生成（Kling、即梦 Jimeng、Vidu、豆包/火山、Sora、Gemini/Vertex、海螺 Hailuo 等）。
- 状态流转：等待中 → 生成中 → 成功 / 失败。
- 任务失败自动退还配额（退款金额等于预扣，可在日志追溯）。
- 视频任务支持续作/重混（Remix），并在重试时锁定到原任务渠道、继承时长/分辨率等计费参数。

## 7. 管理员端功能需求

### 7.1 渠道管理（`/console/channel`）

**用户故事**：作为管理员，我希望灵活配置多家服务商渠道、做负载与容灾，并能按需改写请求参数。

**功能说明**
- 添加渠道：选服务商类型 → 填名称与 API Key → 勾选支持模型（或填入默认模型）。当前支持 50+ 种上游服务商类型（OpenAI、Azure、Claude、Gemini、百度、阿里、智谱、讯飞、腾讯、DeepSeek、xAI、Cohere、Mistral、AWS Bedrock、Vertex、Ollama、SiliconFlow，以及 Midjourney、Suno、Kling、即梦、Vidu、Sora 等多模态/任务型渠道）。
- 高级配置：Base URL、优先级（越高越优先）、权重（同优先级随机）、模型映射、参数覆盖、自动禁用阈值、标签。
- 渠道测试：单测/批量测试，展示响应时间与成功/失败；支持按配置周期自动巡检测试（`auto_test_channel`）。
- 批量操作：批量启用/禁用/打标签。
- 多 Key 模式：单渠道配多 Key 自动轮询，失败跳过、恢复重启用；轮询模式支持「顺序轮询（polling）」与「加权随机（random）」两种。
- 列表展示：名称、类型、状态、响应时间、已用配额。

**渠道选择逻辑（业务视角）**

1. 按令牌分组与请求模型筛选可用渠道。
2. 取最高优先级渠道集合。
3. 同优先级内按权重随机。
4. 渠道内按轮询模式选择 Key。
5. 调用失败则切换下一个 Key/渠道；连续失败达阈值且开启自动禁用，则禁用该渠道。

**验收标准**
- 高优先级渠道优先；同级按权重随机。
- 多 Key 单 Key 失败自动切换不影响整体可用。
- 开启自动禁用后，连续失败达阈值的渠道被禁用。
- 模型映射生效时上游收到映射后的真实模型名。

#### 7.1.1 参数覆盖系统

**用户故事**：作为管理员，我希望按条件动态改写请求参数，以适配不同上游或统一策略。

**功能说明**
- 简单模式：直接指定字段与值，合并进原始请求（如统一设置 temperature、max_tokens）。
- 高级模式：通过操作列表定义复杂改写，支持条件判断。
  - 操作类型：设值、删除、移动、追加、前置、复制、去前缀/后缀、确保前缀/后缀、去空白、转大小写、子串替换、正则替换。
  - 条件匹配：完全/前缀/后缀/包含/大于/大于等于/小于/小于等于；支持反选、缺失字段处理；逻辑支持 AND/OR。
  - 路径支持嵌套字段与数组下标（含负索引），并提供「重定向前/后模型」等内置变量用于条件判断。
- 操作按定义顺序依次执行，前序结果影响后续。

**验收标准**
- 仅当条件满足才执行对应操作。
- 子串替换的匹配源为空时报错；正则非法时报错。
- 「保留原值」开启时已有值的字段跳过设值。
- 操作顺序影响最终结果可被验证。

#### 7.1.2 渠道亲和（粘性路由）

**用户故事**：作为管理员，我希望同一会话/同一对象的请求尽量命中同一渠道，以利用上游侧的会话缓存、对话连续性或对象（如视频任务）一致性。

**功能说明**
- 按规则提取「亲和键」（来源可为请求头、请求体字段、模型名、路径等），在配置 TTL 内将携带相同键的请求粘到首次命中的渠道。
- 规则可按模型/路径正则匹配生效；可配置最大缓存条目数、默认 TTL、命中成功后是否切换、渠道被禁用时是否保留亲和等策略。
- 与多 Key/优先级/权重的常规选路逻辑协同：亲和优先，未命中或亲和失效时回落到常规选路。

**验收标准**
- 同一亲和键在 TTL 内稳定命中同一渠道；TTL 过期后重新选路。
- 亲和渠道被禁用且未开启「保留」时，自动回落到常规选路而非整体失败。

### 7.2 用户管理（`/console/user`）
- 编辑用户：角色（普通/管理员）、分组、配额余额、状态（启用/禁用）、管理员备注（remark）。
- 查看用户的邀请数据（邀请码、邀请人数、累计/可用返利配额）与请求计数。
- 禁用后用户无法登录。
- 按用户名/邮箱关键词实时搜索。

**验收标准**：角色修改后立即生效；配额可直接设置；建议保留至少一个管理/Root 账号，防止误降级导致失管。

### 7.3 兑换码管理（`/console/redemption`）
- 批量生成：名称（批次）、面值、数量。
- 列表展示码值（部分遮挡）、面值、状态、创建时间。
- 支持导出文件便于分发。

**验收标准**：兑换码全局唯一；已使用不可再兑换；导出含完整码值。

### 7.4 日志与统计（管理员视角，`/console/log`）
- 比普通用户多「用户名」「渠道名」列，可见全部用户记录。
- 过滤：时间范围、用户名、模型、渠道、令牌名。
- 统计面板：全平台调用量汇总。
- 数据看板：全平台消耗趋势 + 各用户消耗占比。

### 7.5 订阅计划管理（`/console/subscription`，管理员视角）
- 创建套餐：名称、价格、有效期类型（日/周/月/自定义天数）、含配额；创建后默认下架。
- 上架/下架：上架后可见可购；下架不影响已购订阅。
- 手动开通：输入用户名/邮箱 + 选套餐 → 确认 → 立即生效。

### 7.6 模型管理（`/console/models`）
- 添加/编辑模型：名称、输入价格、输出价格、所属厂商（Vendor）等。
- 厂商管理：维护模型所属厂商/品牌，便于在定价页与管理界面分组展示。
- 同步上游：拉取上游模型列表 → 预览「新增/变更/删除」→ 确认应用。
- 倍率同步与体检：可比对当前倍率配置，识别使用默认倍率（37.5/1.0）的「疑似未配置」模型并提示完善。

**验收标准**：同步预览须区分三类变更；未点应用前不改动本地配置。

### 7.7 分组管理
- 用户分组（编辑用户时指定）、令牌分组（创建令牌时指定）、渠道分组（添加渠道时限定可访问分组）。
- 令牌分组设 `auto` 时按优先级自动选可用分组，支持跨分组容灾（令牌可开启「跨组重试」）。
- 自动分组（`auto_groups`）：定义可被自动选择的分组集合，并可设是否默认启用自动分组。
- 可用分组（`user_usable_groups`）：定义用户可见/可选的分组及其描述。
- 跨组计费倍率（`group_group_ratio`）：可为「某用户组使用某渠道分组」设定专属倍率（如 VIP 用户使用某分组享 0.9 折）。
- 不同分组用户只能使用其被授权的渠道。

## 9. 计费规则

### 9.1 配额单位
1 美元 = 500,000 配额点数。用户余额与消费均以配额计。

### 9.2 三层倍率
- 模型倍率：模型基础计费倍数。
- 补全倍率：输出 Token 额外计费倍数。
- 分组倍率：用户组差异化倍数。
- 优先级：用户专属倍率 > 分组倍率 > 默认倍率。

### 9.3 计费方式
- 按量计费：`(输入Token + 输出Token × 补全倍率) × 模型倍率 × 分组倍率`。
- 按次计费：`模型固定价格 × 分组倍率 × 500,000`（用于绘图、视频、任务型模型等）。
- 音频模型：含音频输入/输出 Token 与音频倍率的特殊计费（系统自动处理）。
- 缓存计费（Prompt Caching）：缓存读取 Token 按折扣计费（典型 10%~50%）；缓存写入按基础价的倍数计费（5 分钟 TTL 与 1 小时 TTL 分别有不同倍率）。
- 工具计费：Web 搜索、文件检索等工具调用按次/按量附加计费，单独计入消耗明细。
- 表达式动态/阶梯计费：见 9.3.1。

#### 9.3.1 表达式计费系统（动态/阶梯定价）

**产品价值**：以「一个模型一条表达式」承载该模型的全部定价逻辑（基础价、阶梯价、缓存/图像/音频分项价、按时间/按请求上下文的动态系数），取代分散的多张配置表，做到「表达式即唯一真相」——相同 Token 与请求上下文，表达式始终得出相同费用。

**能力概览**
- 可视化编辑（选价格/设阶梯）或原始模式（直接编辑表达式），保存时即时编译并冒烟校验。
- 变量覆盖输入/输出各分项 Token：输入 Prompt、上下文长度（用于阶梯条件）、缓存读取、缓存写入（5 分钟/1 小时）、图像输入、音频输入；输出补全、图像输出、音频输出。
- 内置函数：`tier(名称, 费用)` 记录命中的阶梯；`param(路径)`/`header(键)` 读取请求体/请求头；时间函数（hour/weekday/month 等）；数学函数（max/min/ceil/floor 等）。
- 自动分项扣减：当表达式使用了缓存/图像/音频等子类 Token 时，系统自动从 Prompt/补全 Token 中扣除这些已单独计价的部分（仅对 GPT 系格式生效，Claude 系单独处理），避免重复计费。
- 请求级规则：可在表达式后追加条件系数（如命中某请求头时整体乘以倍数）。
- 表达式带版本前缀（如 `v1:`），用于约束编译环境、Token 归一化与配额换算公式的演进。

**全链路**：编辑器 → 存储（每模型一条计费模式与表达式）→ 预消费（用估算 Token 跑表达式，冻结计费快照）→ 结算（用实际 Token 重跑，多退少补）→ 日志展示（在日志中注入计费模式、表达式与命中阶梯，前端解码后渲染定价明细）。

**验收标准**
- 同一组 Token 与请求上下文，预消费与结算使用同一冻结快照，结果可复现。
- 表达式编译失败或冒烟校验不通过时阻止保存并提示。
- 日志可还原每笔计费的命中阶梯与分项构成。

### 9.4 预消费 / 后消费
- 调用前按预估 Token 预扣；调用完成后按实际重算并多退少补；调用或任务失败全额退还。
- 调用前余额不足以覆盖预估消耗时拒绝调用。

### 9.5 未定价模型
- 自用模式使用默认倍率 37.5；商业模式返回「倍率或价格未配置」错误；管理界面标识未配置模型。

### 9.6 计费示例（可作为测试基准）

| 场景 | 参数 | 结果 |
| --- | --- | --- |
| GPT-4 标准用户 | 输入1000/输出500，模型15，补全2，分组1.0 | 30,000 点（$0.06） |
| GPT-3.5 VIP | 输入2000/输出1000，模型0.25，补全1.33，分组0.5 | 416.25 点（≈$0.00083） |
| Midjourney 按次 | 固定价$0.02，分组1.0 | 10,000 点（$0.02） |

## 10. 业务规则与约束

1. 配额单位：1 美元 = 500,000 配额点数。
2. 计费叠加：消耗 = Token × 模型倍率 × 分组倍率（输出额外乘补全倍率）。
3. 令牌 Key 仅创建时展示一次，不可再查看。
4. 2FA 备用码仅展示一次，丢失需管理员重置。
5. 异步任务失败自动退款。
6. 未定价模型：用户侧默认拒绝；系统侧自用默认倍率 37.5，商业模式报错。
7. 启用 OIDC 必须同时开启「允许新用户注册」+「允许通过 OIDC 登录」。
8. 重置 API 密钥后所有现存令牌失效，需重建。
9. 无限配额令牌仍受账户总配额约束。
10. 套餐下架不影响已购订阅。
11. 调用前余额不足覆盖预估消耗即拒绝。
12. 分组隔离：用户/令牌只能使用其分组被授权的渠道。

## 11. 假设、依赖与风险

### 11.1 关键假设
- 上游服务商保持 API 兼容性与可用性。
- 用户具备基本 API 调用能力，或通过操练场零代码验证。
- 运营方已获得对外提供 AI 转售服务所需的资质与合规授权。

### 11.2 外部依赖

| 依赖 | 用途 | 影响 |
| --- | --- | --- |
| 上游服务商 API | 实际模型推理 | 上游故障/限流直接影响可用性 |
| 支付网关（EPay/Stripe/Creem/Waffo/Waffo Pancake） | 充值收款与订阅 | 网关故障影响充值与变现 |
| SMTP 邮件服务 | 验证码、通知 | 未配置则注册/找回/通知不可用 |
| OAuth/OIDC 提供商 | 第三方登录 | 提供商故障影响对应登录方式 |
| Cloudflare Turnstile | 人机验证 | 影响注册风控 |
| Midjourney-Proxy | 绘图任务 | 未部署则绘图功能不可用 |

### 11.3 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 上游单点故障导致调用失败 | 高 | 多渠道、多 Key、优先级+权重、自动禁用与恢复 |
| 计费账实不一致（并发/异常退出） | 高 | 预/后消费 + 失败退款 + 对账机制 |
| 令牌泄露被盗刷 | 中 | 配额上限、模型限制、IP 白名单、重置密钥 |
| 支付回调被伪造 | 高 | 回调强制验签 |
| 未定价模型导致意外高额消耗 | 中 | 用户侧默认拒绝、商业模式报错、管理界面标识 |
| 滥用与刷量 | 中 | 全局/分组限流、人机验证、IP 记录 |

## 12. 计费边界与对账

计费为平台最高风险域，除计费规则外需明确以下边界：

- 并发扣费一致性：同一令牌/账户并发调用时，配额扣减不超扣、不漏扣。
- 退款幂等：同一笔失败调用/任务仅退款一次。
- 充值幂等：支付网关重复回调时同一订单仅入账一次。
- 预扣释放：调用异常中断（超时、断流）时预扣配额可靠释放或按实际结算。
- 对账能力：提供按用户/渠道/时间维度的消耗与充值对账视图。
- 精度与取整：配额计算的小数精度与取整规则统一，避免累计误差。

**验收标准**
- 高并发下账户配额不被扣成负数或超额调用成功。
- 模拟重复支付/退款回调，最终金额与单次一致。
- 任一调用在日志中均可追溯扣费、退款明细。

## 13. 通知与消息触达体系

| 渠道 | 适用场景 | 配置位置 |
| --- | --- | --- |
| 邮件 | 注册验证码、找回密码、配额不足、令牌过期、系统公告 | 个人设置 / 系统邮件服务器 |
| Webhook | 用户侧事件推送（JSON：事件类型+时间戳+详情） | 个人设置 |
| 站内公告 | 首页公告（Markdown） | 系统设置-通用/其他 |

**通用要求**
- 事件可订阅：用户可按事件类型选择是否接收。
- 可测试：Webhook、邮件服务器均支持连通性测试。
- 失败可见：发送失败需有可读反馈，不静默丢失。
- 触达去重：同一事件短时间内避免重复轰炸（按用户+事件类型限流）。
- Webhook 安全：推送带 HMAC-SHA256 签名（`X-Webhook-Signature`），并受 SSRF 出站防护策略约束。

## 14. 内容安全与出站防护

### 14.1 敏感词过滤
- 对请求 Prompt（及可选的补全内容）进行敏感词检测，命中后可「立即停止生成」或「替换敏感词」。
- 可配置：总开关、是否检测 Prompt、命中处置策略、敏感词列表、流式场景缓存队列长度。
- 用途：满足内容合规与平台可接受使用政策（AUP）要求。

### 14.2 SSRF / 出站请求防护
- 对平台发起的出站请求（Webhook 推送、上游模型抓取、远程资源拉取等）做安全管控。
- 可配置：防护开关、是否允许私有 IP、域名黑白名单、IP 黑白名单、放行端口。
- 用途：防止经由用户可控输入触发对内网/敏感地址的请求（SSRF）。

## 15. 全局体验通则

- 空状态：列表无数据时展示引导（如「暂无令牌，点击创建」）。
- 加载态：异步操作展示进度/骨架屏，避免无反馈。
- 错误态：接口失败给出可读错误与可重试入口；区分用户错误与系统错误。
- 二次确认：删除、重置密钥、批量禁用等不可逆/高影响操作须确认。
- 一次性信息保护：令牌 Key、2FA 备用码仅展示一次，提供复制并提示妥善保存。
- 国际化：界面与文档支持多语言（zh/en/ja），文案不硬编码。
- 响应式：控制台主要页面适配桌面与移动端浏览。
- 复制即用：API 地址、模型名、邀请码等高频复制项提供一键复制。

## 16. 合规与可接受使用

平台对外提供 AI 能力转售，需满足合规要求（详见仓库 LEGAL 与可接受使用政策）：

- 可接受使用政策（AUP）：明确禁止用途（违法内容、滥用、攻击等），违规账号可被禁用。
- 支付合规：聚合支付网关本身不等同持牌支付机构，资金清结算依赖其对接的持牌渠道，运营方须遵循所在地监管与风控要求。
- 数据与隐私：IP 记录、调用日志等涉及用户数据，需明确留存周期（日志保留天数可配置）与用途。
- 内容责任边界：平台为中转方，模型输出内容的合规责任边界需在服务条款中界定。

## 21. 术语表

| 术语 | 释义 |
| --- | --- |
| 配额 Quota | 平台内部计费单位，1 美元 = 500,000 点 |
| 令牌 Token | 调用 API 的凭证，可独立配额/限模型/限 IP |
| 渠道 Channel | 对接上游服务商的配置单元，对应一组 API Key |
| 分组 Group | 隔离渠道访问权限与计费倍率的逻辑单位 |
| 模型倍率 | 模型基础计费倍数 |
| 补全倍率 | 输出 Token 额外计费倍数 |
| 分组倍率 | 用户组差异化计费倍数 |
| 预/后消费 | 调用前预扣、调用后按实际重算的双重计费机制 |
| 多 Key 模式 | 单渠道多 Key 轮询容灾（顺序轮询 / 加权随机） |
| 参数覆盖 | 按条件动态改写请求参数的能力 |
| 渠道亲和 | 同一亲和键的请求在 TTL 内粘到同一渠道的粘性路由 |
| 表达式计费 | 单模型单表达式承载全部定价逻辑的动态/阶梯计费 |
| 签到 | 每日一次的随机配额奖励运营机制 |
| SSRF 防护 | 对平台出站请求做内网/敏感地址访问管控的安全机制 |
| 易支付 | 第三方聚合收款网关模式的泛称 |
