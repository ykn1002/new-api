# 人民币锚定改造方案

> 配套文档：积分产品化账本见 [`Token-Plan-技术方案.md`](./Token-Plan-技术方案.md)。
>
> 本方案在「积分产品化账本」之上，把系统的**计价锚点从美元改为人民币**，使本项目成为面向国产模型的「人民币 + 自定义货币（积分）」产品：页面不出现任何美元 / USD / `$`，积分与人民币直接锚定、不经美元中转。所有引用的现状代码均经源码核对（标注 `文件:行号`，基于 `token-plan-rmb` 分支快照）。

## 0. 设计总原则

1. **不动 quota 内核，只改锚点语义。** 系统内部唯一计费单位是整数 `quota`，唯一物理锚点是 `QuotaPerUnit`（`common/constants.go:62`，默认 `500000`）。当前含义是「1 美元 = 500000 quota」。**本方案保持该数值不变，仅把它的含义重新定义为「1 元 = 500000 quota」**。这样 `quota / QuotaPerUnit` 算出来的天然就是人民币，美元概念从整条链路消失。结算内核（`service/text_quota.go`、`service/quota.go`、`relay/helper/price.go`）零改动。
2. **积分直接锚人民币，不经美元。** 积分换算公式 `积分 = (quota / QuotaPerUnit) × CustomCurrencyExchangeRate`（`controller/credit.go:68`）**一行不改**——因为 `quota / QuotaPerUnit` 由「美元」自动变成「元」，`CustomCurrencyExchangeRate` 的语义随之从「1 美元 = X 积分」变成「**1 元 = X 积分**」。
3. **锚定比例：1 元 = 100 积分。** 即 `CustomCurrencyExchangeRate` 默认值设为 `100`。单位名为「积分」，显示形如「积分 12.50」（前缀写法，复用现有单字符 symbol 机制，不新增单位名字段）。
4. **显示默认积分、保留可切换。** 展示模式默认锁定 `CUSTOM`（积分），后台仍保留 `CNY` / `TOKENS` 切换能力，但**移除 `USD` 选项**并清理所有 `$` 硬编码漏出点。
5. **下线外币支付，代码保留。** Stripe / Creem / Waffo / Waffo Pancake 四个外币渠道在充值入口默认隐藏（开关关闭），controller / setting / 前端组件全部保留，日后可恢复。人民币渠道保留微信支付 + 易支付。
6. **默认模型价格保留数值、语义改为元。** `defaultModelRatio` / `defaultModelPrice`（`setting/ratio_setting/model_ratio.go`，约 200+ 条）数值不动，锚点重定义后自动从「美元基准」变为「元基准」。国产模型由运营后续按需重新定价。
7. **三库兼容 + JSON 收口 + 标识保护。** 遵循 CLAUDE.md Rule 1/2/5：JSON 走 `common.*`，三库兼容，不改 new-api / QuantumNous 标识。本方案以「改默认值 + 显示漏点 + 支付开关」为主，几乎不涉及新表 / 新列。

## 1. 核心原理与换算验证

整个换算链路只有 `QuotaPerUnit` 一个锚点。把它的语义从「每美元」改成「每元」后，所有公式不变，只是单位从美元变人民币。配合「1 元 = 100 积分」，验证如下（公式均不改，只改默认值）：

| 场景 | 当前（美元锚） | 改造后（人民币锚，rate=100） | 公式 |
|---|---|---|---|
| 充值 1 元 | — | `1 × 500000 = 500000 quota` → `100` 积分 | `quota = 元 × QuotaPerUnit`；`积分 = quota/QuotaPerUnit × 100` |
| `gpt-4o` ratio=1.25，1M 输入 token | 1.25M quota = $2.5 | 1.25M quota = **¥2.5** = **250 积分** | ratio 模式纯 token×倍率，锚点语义变 |
| `dall-e-3` price=0.04/次 | $0.04/次 | **¥0.04/次** = **4 积分/次** | `quota = price × QuotaPerUnit × groupRatio` |
| 100 积分代充 | — | `100/100 × 500000 = 500000 quota` = ¥1 | `quota = units/rate × QuotaPerUnit`（`credit_admin.go:23`） |

正反向自洽，1:100 比例下积分数字干净（1 元 = 100 积分，最小到分 = 1 积分）。

### 完整换算链路（改造后）

```
[模型定价]  ratio（无量纲，锚定 ¥0.002/1K） / price（元/次） / tiered（元/1M tokens）
      │
      ▼
[请求计费]  service/text_quota.go：内核不变
   ratio:  quota = Σ(token × ratio) × (modelRatio × groupRatio)
   price:  quota = modelPrice × QuotaPerUnit × groupRatio      ← QuotaPerUnit 现在=「每元」
      │
      ▼  AlignQuotaToDisplayPrecision（CUSTOM 按「分」对齐，默认开启）
[实际扣费]  User.Quota -= quota；批次账本分摊（Token-Plan 已实现）
      │
      ▼
[显示]  logger.go FormatQuota / 前端 currency.ts
   CUSTOM: quota/QuotaPerUnit × 100 → 「积分 12.50」   ← 默认
   CNY:    quota/QuotaPerUnit × 1   → 「¥12.50」        ← USDExchangeRate 改为 1
   TOKENS: quota 原值
   （USD 选项移除）
[充值反向]  微信/易支付：金额(元) × QuotaPerUnit → +User.Quota / 积分批次
```

### 2.2 移除 USD 展示选项

- `setting/operation_setting/general_setting.go`：`GetCurrencySymbol()`（:60）/ `GetUsdToCurrencyRate()`（:77）保留 CNY / TOKENS / CUSTOM 分支，移除 `USD` 分支（或令其回退到 CUSTOM）。
- `logger/logger.go:122` `LogQuota` / `FormatQuota`：同步去掉 USD 分支，default 落到 CUSTOM。

### 2.3 RechargeTier 双口径统一（隐患修复）

调研发现同一充值档位存在两套口径（详见 [`Token-Plan-技术方案.md`](./Token-Plan-技术方案.md)）：
- 微信支付 `controller/topup_wechat.go:62-74`：用 `tier.Amount`（元）→ `quota = money × QuotaPerUnit`；
- 管理员代充 `controller/credit_admin.go:43,62`：用 `tier.BaseCredits`（积分）→ `creditUnitsToQuota`。

锚点统一为「元」后，应以 `tier.Amount`（元）为唯一定价基准，`BaseCredits` 由 `Amount × 100` 派生（后台可覆写），避免改了 Amount 而 BaseCredits 未同步导致两条充值路径到账不一致。

### 2.4 不改动的部分

- `service/text_quota.go` / `service/quota.go` / `relay/helper/price.go`：结算内核与货币无关（ratio 纯 token×倍率，price 才乘 `QuotaPerUnit`）。
- `controller/credit.go` / `controller/credit_admin.go` 积分换算公式：随锚点语义自动变正确，不改。
- 微信支付链路（`topup_wechat.go`）：已是「元」口径（currency 固定 CNY、金额单位元），无需改。
- 积分批次账本（`model/credit_batch.go`）：存的是 quota 整数，与口径无关。

## 6. 风险与注意

1. **存量数据语义变化。** `User.Quota`（quota 整数）值不变，但标称价值从 $X 变 ¥X（等于按 1:1 重新标价）。全新部署无影响；存量美元计价库等于整体改了计价口径——这正是「改成人民币主导」的预期目标，需运营确认。
2. **OpenAI 兼容计费接口**（`controller/billing.go` 输出的 `*_USD` 字段）：为保 API 兼容**不改字段名**，但值已变为元 / 积分口径。前端不展示，优先级低，文档注明即可。
3. **Redis / DB 已存的 option 覆写值。** 本方案改的是 Go 默认常量，仅对全新部署生效。存量库需手动把相关 option（`quota_display_type`、`custom_currency_exchange_rate`、`usd_exchange_rate`、`Price` 等）调成新值，或写一次性迁移。
4. **失败回滚。** 全部改动为默认值 / 开关 / 显示层，无 schema 变更，回滚只需还原常量与开关。
