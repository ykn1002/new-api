# Token Plan 方案

> 本文档由 `Token Plan方案.docx` 转换而来。原文档中的 18 张配图（后台界面原型、小程序原型、业务流程图）已逐一转写为文字化的需求描述，以「界面需求」或「流程需求」区块的形式内嵌在对应位置。

## 需求总览（六条核心需求）

1. **后台「模型 Tokens–积分」换算设置**：支持新增不同模型，并分别配置每个模型的积分消耗（区分输入/输出 Token 单价，单次消耗积分保留两位小数）；设置一个默认模型，用户不可自行选择。

2. **「人民币 → 积分 → Tokens」计费链路**：客户充值获得积分，后台配置充值汇率（默认 1 元 = 100 积分）；积分再按各模型计费规则抵扣 Tokens 消耗。

3. **充值档位与积分有效期**：用户仅通过充值档位购买积分，不提供套餐购买、不限购买次数；后台可配置充值档位；积分设有效期，到期未用清零，多次购买顺延。

4. **用户额度与充值**：每个用户积分额度有限，临近用尽或用尽时可自助充值（积分概念）；运营也可在运营后台为用户代充值。

5. **小程序「我的」积分充值**：用户在小程序「我的」页面完成积分充值，并查看余额、有效期与积分明细。

6. **统一流量池**：平台拥有统一的大流量池，可查看整体流量情况与总 Token 消耗（含每个用户消耗）；本期仅做监控与统计，不做流量管控。

# 概述

## 背景与目标

平台对外以**积分**作为统一计费货币，底层以 **Tokens** 计量 AI 模型的真实消耗。用户通过购买**套餐**或**充值**获得积分，在调用模型时按各模型的换算规则扣减相应积分。平台侧维护统一的**流量池**，用于监控并管控整体 Token 消耗。

本需求要达成的目标：

1. 建立"人民币 → 积分 → Tokens"清晰、可配置的计费链路；
2. 支持套餐化运营（如 199 元/月）与充值积分；
3. 运营后台可自助配置套餐、充值档位与各模型计费规则；
4. 平台可对整体及单用户的 Token / 积分消耗进行全局监控与管控。

## 核心概念定义

| 概念 | 说明 |
|:---|:---|
| 积分 | 面向用户的计费单位，用户充值/购买套餐后获得，调用模型时扣减。用户侧主要感知积分。 |
| Tokens | 模型计量单位（输入+输出），用于平台统计真实消耗成本，不直接对用户结算。 |
| 套餐 | 运营预置的"价格+赠送积分+有效期"组合，如 199 元/月赠 20000 积分。 |
| 充值档位 | 按金额充值获得积分的档位，如充 100 元得 10000 积分。 |
| 充值汇率 | 人民币与积分的基础兑换比例，默认 1 元 = 100 积分，后台可配。 |
| 模型计费规则 | 某模型每消耗一定 Tokens 所扣减的积分数，逐模型可配，可区分输入/输出。 |
| 流量池 | 平台维度的 Token 总消耗与配额视图，支持总量与单用户监控、管控。 |
| 积分账户 | 记录单个用户的积分余额、累计充值/消耗、有效期等。 |
| 积分流水 | 用户每一笔积分变动（充值、赠送、消耗、过期等）的明细记录。 |

## 计费链路

整体资金与消耗链路如下：

**人民币** ──（充值汇率：1 元 = 100 积分）──▶ **积分** ──（模型计费规则：每千 Tokens 扣 N 积分）──▶ 抵扣 **Tokens** 消耗

同时，所有用户的真实 Token 消耗汇入**流量池**，供平台做总量统计、成本核算与流量管控。

## 关键换算关系（默认值，均可后台配置）

1. tokens 与 人民币的计费（成本）
2. 人民币成本 到 人民币 收入
3. 人民币收入 到 积分

| 项目 | 默认值 | 是否可后台配置 |
|:---|:---|:---|
| 充值汇率 | 1 元 = 100 积分 | 是 |
| 默认套餐 | 199 元 / 月，赠送 20000 积分，有效期 30 天 | 是 |
| 模型计费 | 按模型设定"每 1000 Tokens 扣减积分数"（区分输入/输出） | 是 |
| 积分取整规则 | 单次消耗积分保留两位小数 | 是 |

注：199 元按基础汇率应得 19900 积分，套餐额外赠送 100 积分凑整为 20000，体现套餐相对零散充值的优惠；具体数值以运营后台配置为准。

## 模型 Tokens-积分换算设置

**目标：** 后台可设置每个模型的"Tokens → 人民币"换算规则，并支持新增不同模型、配置不同的积分消耗。

### 功能点

- 模型列表：展示已接入模型及其计费规则与状态。

## 用户额度与充值

**目标：** 每个用户的积分额度有限，临近用尽或用尽时可由用户自助充值，运营也可在后台代为充值。

### 积分数据模型

积分相关的字段其实分属两个维度，先把它们分清楚，页面才不会乱：来源构成回答"钱从哪来"（都是加项），去向流水回答"账怎么花掉"（都是减项）。

**维度 A — 余额的「来源构成」（都是 +）**

描述积分余额的组成，是"当下状态"，三类来源相加即为当前可用总积分。

| 类型 | 含义 | 通常特点 |
|:---|:---|:---|
| 赠送积分 | 注册 / 活动 / 补偿 / 赠送 | 有效期短，优先扣减 |
| 套餐积分 | 订阅套餐每周期发放 | 跟随套餐周期，到期清零 |
| 充值积分 | 用户实付购买 | 有效期长，最后扣减 |

**当前可用总积分 = 赠送余额 + 套餐余额 + 充值余额**

**维度 B — 积分的「去向流水」（都是 -）**

描述积分如何被花掉，是"历史累计"（流量数据），不参与当前余额的加减。

| 类型 | 含义 |
|:---|:---|
| 已消费 | 调用模型 / 技能扣掉的积分 |
| 已过期 | 到期未用、被系统清掉的积分 |

### 页面结构

**① 页头 pageHead**

- 返回入口：← 返回用户积分管理
- **用户信息块：** 头像 / 手机号 · UID / 当前套餐标签 / 状态标签
- **右上角主操作：**「积分充值」按钮 → 复用已有的代充值弹窗

**② 总积分概览**

- **当前可用总积分**（大号数字突出展示）
- 旁边小字：最近一笔即将过期提示，如「2,000 将于 6 月 30 日过期」，并附低余额预警标识。

**③ 积分构成 — 来源拆分**

- **三张并排卡片：** 赠送 / 套餐 / 充值，每张显示「余额 + 有效期 + 占比」。
- 卡片上方可加一条**堆叠占比条**，一眼看出三类比例。
- 本区块直接回答「总积分由什么构成」。

## 流量池运营看板

**目标：** 平台拥有统一的"大流量池"，可查看整体流量情况、管控整体流量，可查看总 Token 消耗及每个用户的 Token 消耗。

### 监控

- **总览仪表盘：** 总 Token 消耗、总积分消耗、对应成本估算、累计充值金额、用户总数/活跃数。
- **多维统计：** 支持按时间（日/周/月）、按模型、按用户三个维度查看消耗趋势与排行。
- **用户明细：** 列表展示每个用户的 Token 消耗、积分消耗、积分余额，可下钻到该用户的消耗流水。
- **模型明细：** 各模型的调用次数、Token 消耗、积分消耗占比。
- **数据导出：** 支持按筛选条件导出统计与明细（Excel/CSV）。

### 管控

| 管控能力 | 说明 |
|:---|:---|
| 总流量上限/告警阈值 | 设置平台整体 Token 消耗的告警线与上限，达到阈值触发告警。 |
| 单用户限额 | 限制单用户单位时间（如每日）最大 Token/积分消耗，防滥用。 |
| 暂停 | 可一键暂停某模型或全部模型的调用（如成本异常、上游故障）。 |
| 黑/白名单 | 对异常用户进行限制或加白（可选）。 |

说明：监控数据来源于每次模型调用的 Token 计量与积分扣减记录，需保证调用日志与流水的一致性。

# 关键业务流程

## 4.1 购买套餐 / 充值流程

1. 用户选择充值档位；
2. 生成充值订单（记录金额、应得积分、赠送积分）；
3. 调起支付并等待支付回调；
4. 支付成功后按积分并入账；
5. 写入积分流水（类型=充值/购买积分档位），更新积分余额与有效期。

## 4.2 模型调用与积分扣减流程

1. 用户发起模型调用请求；
2. **校验积分余额是否充足（细化）**、账户是否在有效期、是否触发限流/熔断；
3. 调用模型并获得实际输入/输出 Tokens；
4. 按该模型计费规则换算应扣积分（含取整）；
5. 扣减积分、写入积分流水（类型=消耗），同时将 Token 消耗汇入流量池统计；
6. 若余额低于预估阈值，返回余额不足提醒。
