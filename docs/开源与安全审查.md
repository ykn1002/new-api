# new-api 开源性与安全审查

> 目的：核实本项目是否完全开源、是否存在订阅后门 / license 校验 / 远程开关 / phone-home（回家上报）等隐藏机制。
>
> 结论速览：**完全开源（AGPL-3.0，强 copyleft）；未发现订阅后门、license 校验、远程开关或隐藏遥测。** 唯一对外可选项是「需自行开启」的前端 Analytics，默认关闭。

## 一、授权协议：AGPL-3.0（真开源）

- `LICENSE` 为标准 GNU Affero General Public License v3.0；`NOTICE` 标注 `Copyright (c) QuantumNous and contributors`，全项目 AGPLv3。
- **Section 7 附加条款（合法附加，必须遵守）**：
  - 修改版须保留署名「Frontend design and development by New API contributors」；
  - 须在 about/footer/legal 等显著位置保留指向原仓库的可见链接：`https://github.com/QuantumNous/new-api`；
  - 不得伪称来源，须按 §7(c) 标注修改。
- **§13 网络条款**：若修改后对外提供网络服务，须向用户提供对应源码。

> 性质：以上是**法律义务**（也对应 `AGENTS.md` 规则 5 的品牌保护），**不是技术锁**——代码不会因此停摆或限制功能。

## 二、是否有订阅后门 / 远程校验：无

| 排查项 | 结果 |
|---|---|
| license 校验 / 激活码 / 授权服务器 | ❌ 无（搜索 `license_key`/`activation`/`verifyLicense`/`checkLicense` 后端零命中） |
| 远程开关 / kill switch | ❌ 无（`killSwitch`/`remote_config`/`feature_flag`/`entitlement` 后端零命中） |
| phone-home / 心跳上报 | ❌ 无（`phone-home`/`heartbeat`/`telemetry` 后端零命中） |
| 版本检查回调作者服务器 | ❌ 无（无 `CheckUpdate`/`GetLatestVersion` 之类） |
| 「订阅」是否为软件授权门控 | ❌ 否，见下 |

**关于「订阅」**：项目中的 `SubscriptionPlan` / `UserSubscription`（`model/subscription.go`）是**面向运营、卖给其自己终端用户的业务功能**（套餐/周期/额度发放），数据全部存本地数据库自管，**不向任何外部服务器校验**。它**不是**对 new-api 软件本身的授权或解锁机制，因此不构成「订阅后门」。

## 三、唯一对外可选项：Analytics（默认关闭，需自行开启）

`main.go` 的 `InjectUmamiAnalytics()` / `InjectGoogleAnalytics()`：

- 仅当运营**自行设置环境变量** `UMAMI_WEBSITE_ID` 或 `GOOGLE_ANALYTICS_ID` 时，才向前端页面注入对应统计脚本（指向你自己的 Umami 实例 / 你自己的 GA）。
- 不设置 → 仅写入一段 HTML 注释，**默认不发送任何数据**。
- 性质：运营自助埋点，**非隐藏遥测**。

## 四、看似敏感但属正常的运营开关

| 开关 | 说明 |
|---|---|
| `SelfUseModeEnabled` | 自用模式；影响「未配置倍率模型」的默认放行行为，运营在 setup/后台自行设置 |
| `DemoSiteEnabled` | 演示站模式 |

均由运营显式设置（`controller/setup.go`、`model/option.go`），非后门。

## 五、正常的对外网络行为（属功能，非后门）

作为 AI 网关，运行时会主动外联**你自己配置的**目标，这是其本职功能、流向由你的配置决定：

- 上游 AI 提供商（OpenAI / 阿里 / 火山 / 智谱 / DeepSeek 等你添加的渠道）。
- 你配置的支付渠道（Stripe / Creem / Waffo / 易支付，及本方案拟接入的微信支付）。
- 可选：你开启的通知渠道（邮件 / Webhook / Bark / Gotify）、你开启的 Analytics。

不存在「向作者/第三方固定服务器上报数据或拉取授权」的行为。

## 六、结论

1. **完全开源**：是，AGPL-3.0 强 copyleft，源码可读可改可自部署。
2. **订阅后门**：无。「订阅」是运营业务功能，非软件授权门控；无 license 校验、无远程开关、无 phone-home。
3. **使用约束**（法律层面，非技术锁）：须保留署名与原仓库链接；对外提供服务须按 AGPL 开放修改后的源码。

## 七、本次审查的范围与局限

- **已做**：读取 `LICENSE`/`NOTICE`；针对 license/激活/远程开关/phone-home/遥测/隐藏开关/外部域名等关键词做全仓源码扫描；核对 analytics 与 subscription 相关代码路径。
- **未做**（如需更高保证建议补充）：
  - 全量逐文件人工审计与第三方依赖深度审查（依赖清单见 `THIRD-PARTY-LICENSES.md`，建议跑 SCA/SBOM 扫描）；
  - 运行期出站流量抓包核对（部署后观测，确认仅去向你配置的上游/支付/可选 analytics）；
  - 构建产物（Docker 镜像 / Electron 安装包）与源码一致性比对。

> 注：本文为基于源码静态审查的工程性结论，非正式法律意见；AGPL 合规细节如有疑问请咨询法务。

## 八、SCA / SBOM 扫描结果

**工具**：osv-scanner 2.3.8（数据源 OSV.dev）。扫描时间见执行记录。命令：
- 后端：`osv-scanner scan source --lockfile=go.mod`
- 前端：先 `bun install --lockfile-only`（web 工作区）生成 `bun.lock`，再 `osv-scanner scan source --lockfile=bun.lock`

### SBOM 依赖清单（规模）

| 部分 | 来源 | 规模 |
|---|---|---|
| 后端 Go | `go.mod` | `go 1.25.1`；55 直接 + 75 间接 require（go.sum 含全部传递依赖） |
| 前端（Bun 工作区 default+classic） | 解析生成的 `bun.lock` | 1635 个解析包 |

> 注：前端仓库未提交 lockfile，本次为临时解析最新匹配版本，**与实际构建产物可能有细微版本差异**；正式核对应以 CI 构建时的 lockfile 为准。

### SCA 漏洞结果（均为第三方依赖/工具链的已知 CVE，非项目代码）

**后端**（受影响包全部是 `golang.org/x/*` 与 Go 标准库/工具链）：

| 包 | 现版本 | 建议修复版本 | 通告数 |
|---|---|---|---|
| golang.org/x/crypto | 0.45.0 | ≥ 0.52.0 | 13 |
| golang.org/x/net | 0.47.0 | ≤ 0.55.0 | 7 |
| golang.org/x/image | 0.38.0 | 0.39.0 / 0.41.0 | 4 |
| golang.org/x/sys | 0.38.0 | ≥ 0.44.0 | 1 |
| Go stdlib/toolchain | 1.25.1 | ≥ 1.25.11 | 36 |

**前端**（1 个传递依赖）：

| 包 | 现版本 | 修复版本 | 通告 |
|---|---|---|---|
| minimist | 1.2.0 | ≥ 1.2.6 | GHSA-xvch-5gv4-984h（CVSS 9.8 严重，原型链污染）、GHSA-vh95-rmgr-6w4m（5.6） |

### 解读与结论

1. **不影响"无后门"结论**：上述全部是**第三方依赖/Go 工具链版本的已知漏洞**（可通过升级修复），**不代表 new-api 自身代码存在后门或恶意逻辑**。SCA 是版本卫生问题，与「订阅后门/远程校验」是两回事。
2. **Go 标准库的 36 条**主要因为 `go.mod` 钉在 `go 1.25.1`；**用最新补丁版 Go（1.25.11+）构建**即可消除绝大部分。
3. **golang.org/x/\* 系列**：升级到上表「修复版本」即可（`x/crypto`、`x/net`、`x/image`、`x/sys`）。
4. **前端 minimist 1.2.0（严重，原型链污染）**：为传递依赖，需在引入它的上游包升级后跟随，或用包管理器 override/resolutions 强制 ≥1.2.6。

### 修复优先级建议

- **高**：前端 `minimist` → ≥1.2.6（CVSS 9.8）；用最新 Go 1.25.x 重新构建后端。
- **中**：升级 `golang.org/x/crypto`、`golang.org/x/net` 到修复版本。
- **低**：`x/image`、`x/sys` 视使用面酌情升级。

### 复现实方式

```bash
brew install osv-scanner
# 后端
osv-scanner scan source --lockfile=go.mod
# 前端（需 bun）
cd web && bun install --lockfile-only && osv-scanner scan source --lockfile=bun.lock
```

> 局限：本次扫描覆盖 go.mod 与前端解析后的 bun.lock；未做运行期出站流量抓包与构建产物一致性比对（见第七节）。漏洞数据随 OSV.dev 更新而变化，建议纳入 CI 定期扫描。
